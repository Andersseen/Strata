**Outcome B.** Nitro exposes its H3 through a public plugin hook, but as an H3 v1 `App` (`use`/`stack`) and v1 `Router`, not an H3 v2 `H3` instance. The current `@strata/h3` cannot mount directly.

`@strata/h3` was **not** mounted in Analog: the only H3 app the public seam provides is an H3 v1
`App`, and passing it to a function typed for the H3 v2 `H3` class would need an unsafe cast
between majors, a fake H3 instance, or a second router — all ruled out for this experiment.

### Experiment: Angular DI through `controllerFactory`

`src/server/plugins/strata-angular-di.ts` registers `AngularDiController` with a factory owned by the
fixture, not by `@strata/analog` (which has no Angular dependency). The plugin creates an app-level
`Injector.create()` holding `AppGreetingService`; for each request the factory creates a child
`Injector.create({ parent: appInjector })` providing `STRATA_REQUEST` and `RequestScope`, and
builds the controller with `runInInjectionContext(requestInjector, () => new Controller())`. The
controller resolves everything with `inject()` in field initializers and keeps it across `await`.
A Nitro `request` hook puts a mutable slot on `event.context` (shared by the request's shallow
context snapshot); `afterResponse` and `error` hooks destroy the injector stored in it.

Two overlapping requests per mode: `?id=a&delay=150` and `?id=b` (B answers while A is suspended).
Stats come from `/api/strata-angular-di-stats` once both have answered.

| Mode              | Responses                                                                                                                                                                                                                                                  | Injector stats                                        |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| production server | `{"requestId":"a","greeting":"hello","appInstance":1,"scopeInstance":2,"sameRequest":true,"destroyedBeforeResponse":false}`<br>`{"requestId":"b","greeting":"hello","appInstance":1,"scopeInstance":1,"sameRequest":true,"destroyedBeforeResponse":false}` | `{"created":2,"destroyed":2,"controllersReleased":2}` |
| dev server        | `{"requestId":"a","greeting":"hello","appInstance":1,"scopeInstance":1,"sameRequest":true,"destroyedBeforeResponse":false}`<br>`{"requestId":"b","greeting":"hello","appInstance":1,"scopeInstance":2,"sameRequest":true,"destroyedBeforeResponse":false}` | `{"created":2,"destroyed":2,"controllersReleased":2}` |

Expected and observed: both requests share one `AppGreetingService` instance, each gets its own
`RequestScope`, the injected `STRATA_REQUEST` is the object the handler receives, no injector is
destroyed before its response, and every request injector (and its controller's `DestroyRef`
callback) is destroyed afterwards. Limits: the app-level injector is created in the Nitro plugin and
is **not** the injector of Analog's SSR application (a Nitro plugin cannot reach that one), and
disposal relies on Nitro hooks because `@strata/analog` exposes no release hook yet. The experiment's

## Blockers discovered

1. **H3 major mismatch at the seam.** Analog 2.7.2 → `nitropack` 2.13.4 → H3 v1. The only
   public H3 handle (`nitroApp.h3App`) is an H3 v1 `App` with no `.on()`. `@strata/h3` needs an H3 v2
   `H3` instance, so it cannot mount directly (Outcome B). Resolved for Analog without
   touching it: `@strata/analog` is a sibling adapter on `nitroApp.router` and does not depend on
   `@strata/h3`. `@strata/h3` stays an H3 v2-only adapter.
2. **Phantom `h3` dependency in `@analogjs/vite-plugin-nitro@2.7.2`.** It imports `h3` without declaring
   it. Under pnpm's default hoisting, in a workspace that also contains `@strata/h3`, the bare import
   resolved to H3 v2 and the Vite config failed to load. This repo now declares the H3 major Nitro 2
   uses through `packageExtensions` in `pnpm-workspace.yaml` (workspace configuration only; no
   Strata code changed). Recorded failure before that workaround:

   ```
   failed to load config from <repo>/apps/analog-fixture/vite.config.ts
   error during build:
   file://<repo>/node_modules/.pnpm/@analogjs+vite-plugin-nitro@2.7.2_…/node_modules/@analogjs/vite-plugin-nitro/src/lib/utils/register-dev-middleware.js:1
   import { createEvent } from 'h3';
            ^^^^^^^^^^^
   SyntaxError: The requested module 'h3' does not provide an export named 'createEvent'
   ```

3. **Angular pipeline treats consumer decorators as legacy** with the stock `experimentalDecorators: true`
   (arm G1, class B). Turning it off makes the dev server work but exposes the next item.
4. **Production SSR of Angular-compiled standard decorators fails on `tslib`** (arm G2-prod, class C):
   TypeScript's standard-decorator lowering imports `__esDecorate`/`__runInitializers` from `tslib`
   (`importHelpers: true`); Nitro traces only `tslib`'s `module`-condition files, so Node's
   `import` + `node` resolution of `tslib/modules/index.js` fails at runtime. SSR then returns HTTP 200
   with an empty router outlet — a silent failure. Not investigated further or fixed here.
5. **Repo-wide Node floor (addressed).** `@angular/build@22` and `create-analog@2.7.2` require Node
   `^22.22.3 || ^24.15.0 || >=26`, and `engine-strict=true` makes `pnpm install` fail below that. The
   root/workspace development floor is now `>=22.22.3`. The public `engines` of `@strata/core`,
   `@strata/h3` and `@strata/analog` stay `>=22`: only the Angular fixture needs the higher patch.
   CI (`node-version: 22`) resolves the latest 22.x; that it satisfies the floor was not verified.
6. **Unchanged, not attempted:** the H3 v2 / crossws declaration blocker from SPEC-001/SPEC-002. The
   fixture never imports `@strata/h3`, so it neither triggers nor hides it.

Non-blocking observations from `pnpm install`: pnpm ignored the install scripts of `esbuild`,
`@parcel/watcher`, `lmdb` and `msgpackr-extract` (builds and servers worked without approving them),
and warns that `@angular/build` wants `vitest@^4.0.8` while the workspace root has `vitest@5.0.1`
(only used by Angular's own unit-test builder, which the fixture does not run).
